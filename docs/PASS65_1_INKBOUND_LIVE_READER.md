# Pass 65.1 — Inkbound Live Reader & Reliable Fades

Baseline: user-provided `root-review-20261020-130945.zip`, with Pass 65.0 integrated. This overlay is **cumulative**: it includes the protected `/dev/inkbound` foundation as well as the new live reader.

## Main changes

- New optional `?reader=inkbound` view on **actual live adventures**. Players can switch back without leaving the room. It connects to the existing `AdventurePage` props and callbacks, not a second socket or fake server.
- Displays authoritative scene title/body/choice list, selected/committed states, Hero HP/XP/active effects, co-op player presence, chat, journal drawer, editable temporary notes, Chronicle turn-history drawer, and Story Time on/off control.
- Existing `TurnTheater`, `HeroDeathModal`, `LevelUpModal`, `QuickEventModal`, and remaining authoritative controls stay mounted in the parent, including server-owned dice and progression logic. Only the standard reader's main layout is hidden while the opt-in reader is active.
- During unresolved/reconnecting story states, does not display unapproved next-chapter prose; the reader keeps a neutral preparing screen. Story text uses ordinary CSS opacity entrances, respecting reduced-motion settings.
- Changes the legacy **live** physical book reader to opacity fades (430ms out / 620ms in). The 33-stage ink masks stay available for old development labs but are explicitly disabled in the production-used book viewer. Cancels obsolete animations when the scene changes.
- Pass 65.0 frontispiece/chapter workshop no longer loads or iterates mask frames. Instead new chapter art fades in using a short CSS opacity animation.
- Replaces all five provisional screenshot-extracted illustration PNGs from Pass 65.0 with **original, standalone, drawn transparent RGBA illustrations** (`north-road`, `hero-vista`, `signpost`, `lantern-books`, `camp-cups`) generated by `scripts/build-inkbound-art.py`. The script verifies alpha and substantial blank margins on all four sides. It neither reads the mockup screenshots nor uses feathered crop edges. Paper grain remains a separate background asset.

## Visual quality and scope

This is a functional implementation pass with **interim original ink line-art**, not final, museum-quality watercolor illustration. The line-art style is intentionally simpler than the user's approved reference. Replacement illustrations should be commissioned/generated as standalone transparent subject images, then evaluated on the real HTML canvas. No screenshot extraction, edge feather or CSS radial masking may be substituted.

The live Inkbound reader is still an **opt-in preview**, not a wholesale reskin of all game routes. Authentication, front page, Hero Hall, authoring tools, inventory UI, complete modal gallery, full Story Time configuration, and Arcade visuals still use their preexisting interface systems. Do not claim the app-wide redesign is complete. Existing modal/overlay components continue to function but not all have the new visual language yet. No backend or infrastructure files changed.

## How to use

1. Install this ZIP using `scripts/install-overlay.sh`.
2. Run your existing `./scripts/release-staging.sh "Pass 65.1: Inkbound live reader and reliable fades"`. It runs checks before Git commit/push/AWS release; do not call `check-project.sh` separately.
3. In a started adventure, click **OPEN INKBOUND READER · PREVIEW**; or append `?reader=inkbound` to a live adventure URL. Use **Standard reader ↗** to exit. New adventure lobbies still use the original functional readiness/start UI.
4. Admins can still inspect `/dev/inkbound` for the art/layout workshop.

## Validation / remaining gates

- The 23 tested existing Inkspace reader / instrument / ink-reliability and new Inkbound Python regression checks passed in this sandbox.
- Changed TSX files passed standalone TypeScript transpilation, CSS parsed successfully.
- RGBA artwork export script enforces transparent edges and >= 9% inset each direction. Assets are shipped prebuilt; the user's Mac does **not** need CairoSVG.

Full checks must pass in the local release script before Git/AWS release. Do not deploy if checks fail.
- Stop-before-deploy on preflight failure is supported. The current release script does **not** guarantee atomic rollback of a partially failed AWS deployment.
