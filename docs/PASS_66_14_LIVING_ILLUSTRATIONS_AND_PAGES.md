# Pass 66.14 — Living Illustrations, Author Art, Rulebook & Legal Pages

## Scope and art identity

- **Unique chapter illustration:** generated **once from the Director's actual committed chapter text**, including its title and the world's setting. `start_adventure` and `commit_director_turn` enqueue illustration jobs after commit, so artwork can render during the remaining intermission/result sequence but cannot slow the authoritative dice/HP/XP state, voice narration, or next-chapter reveal. Guessing the next scene from the player's choice before the Director's response would produce mismatched pictures; this release deliberately does not do that.
- **Catalog covers:** separately authored, durable **one per World and one per adventure Brief**, explicitly requested through the Author Console. A story-specific Brief cover wins; a World cover comes next; otherwise use the small Quillairo genre placeholder library. No art regenerated merely by browsing the atlas.
- **Transparency:** one PNG RGBA, transparent `background`, subject inside at least a 12% prompted margin and a hard server-side **10% alpha margin validator** on all four sides. No painted paper rectangle, no CSS box masks or feathering. Original artwork has an organic silhouette. Source scene art remains on its own layer.
- **Category fallbacks:** currently use three already-approved transparent assets: `home-vista.png`, `living-worlds.png`, `auth-journey.png`. These are interim, not a complete ten-genre bespoke library. All passed the real alpha/margin validator. Replace individually with commissioned category-specific transparent images later without changing React geometry.
- **Dark/light:** same standalone illustrations, dark themes inherit existing page treatments. CSS uses `object-fit:contain` rather than cropping into a rectangle; fade-in is disabled for reduced motion.

## Services / security / budget

- `app/generation/scene_art.py` owns async image generation, durable S3 object identity, event-specific prompt, 10% margin validation, auth and rate limits.
- In-progress jobs run in the API process with a concurrency cap of two. Completed images persist in an **existing private SSE-S3 bucket**; no public ACL. An authenticated participant can only retrieve the current scene's art from their own room.
- An authored World/Brief cover can only be generated by its owner with Author Studio's CSRF/same-origin header; maximum three attempts per document. Other users can retrieve the cover only after the source has a published version.
- Daily paid artwork quota defaults to **60 generation requests/day** (globally); configurable. One attempt per scene, 3 per World/Brief. Rate-limit reservations are transactional and survive process restarts in the shared database.
- Image failures do not fail the game; placeholder stays visible. An existing artwork returned through private S3 is accessible after reconnect/reload.
- A request itself is not a durable SQS job: an API process restart may interrupt an in-flight image request. A production job queue with retries remains recommended for reliable scale. This release does not provision new AWS infrastructure.

### Runtime configuration

- `OPENAI_API_KEY` — image provider credential, existing configuration for Hero portraits.
- `QUILLAIRO_ART_BUCKET` — optional; otherwise use existing `HERO_PORTRAIT_BUCKET`, then `KOKORO_ARCHIVE_BUCKET` (private encrypted S3). Application role requires `HeadObject`, `GetObject`, `PutObject` within this bucket.
- `QUILLAIRO_SCENE_ART_ENABLED=1` — default; set to `0` to immediately disable paid artwork without affecting gameplay.
- `QUILLAIRO_SCENE_IMAGE_MODEL=gpt-image-1` — default.
- `QUILLAIRO_ART_DAILY_LIMIT=60` — global database-backed usage ceiling. Set lower for a tighter spending budget.

If API key / bucket is unavailable, the feature safely remains on genre/author fallbacks. It cannot be confirmed that your AWS deployment has the required permissions until a live staging test.

## Endpoints

- `GET /api/story-art/rooms/{room}/scenes/{scene_id}/status` — authenticated player, status/image path only.
- `GET /api/story-art/rooms/{room}/scenes/{scene_id}/image` — authenticated and room-owned PNG from private S3.
- `POST /api/story-art/worlds/{document_id}/generate` — Author Studio explicit action (World **or** Brief). With `?refresh=1`, regenerate subject to max 3 requests.
- `GET /api/story-art/worlds/{document_id}/status` and `/image` — owner or published document reader.

## Pages converted

- Real reader chapter illustration slot now resolves scene-specific → Brief → World → genre. Its real StoryReveal, sidebar, choices, co-op, and dice callbacks are unchanged.
- Authenticated Discover/browse thumbnails use Brief → World → genre, replacing repeated title-keyword cards.
- Author Studio has a dedicated illustrated-atlas panel for World and Brief versions; the autosaving manuscript/source editor remains untouched.
- Real `/game/rulebook` and public `/rulebook`: editorial manuscript layout in six palettes with preserved mechanical content.
- Public `/privacy` and `/terms`: consistent manuscript folios; original notices and navigation remain. Privacy copy now describes optional scene illustration generation.

## QA / deployment acceptance

1. Run the full existing `./scripts/release-staging.sh` on your Mac. The source was rebuilt from the October 20 project snapshot plus passes through 66.13; there are environment limitations in the packaging sandbox.
2. Open an **existing** adventure; verify text first, genre fallback visible, then newly generated transparent scene image arrives without blanking narration or choices. Repeat with one scene describing modern/scifi events and one fantasy scene; artwork must follow the actual event, not generic castles.
3. Choose → Arcade → committed dice/result → Continue → next chapter. Confirm there was one server roll and the image job never changes turn timing. This live turn flow was reported as unreliable before this pass and remains a mandatory staging check.
4. Reload an ongoing chapter; previously generated art loads via private S3. Switching account or guessing another room's image URL must return 404.
5. Open Author Studio; select a World/Brief and generate its cover. Verify one saved cover reused in Discover, and that generating a story-specific Brief cover overrides its World cover.
6. Verify all six themes, phone scroll, 10% margins, reduced-motion, and Rulebook/Privacy/Terms routes.
7. Monitor S3 permissions, image model cost, daily quota, HTTP 404/503 fallbacks, and process restarts.
